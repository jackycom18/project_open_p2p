## 3. 课题与使用场景

### 3.1 所选课题及理由

选定 **课题六：行为克隆游戏智能体**，以官方开源 **Open P2P** 为参考实现，扩展方向为**文本指令**。

选用理由（两句话）：行为克隆方法成熟、可复现，150M 档模型单卡 8–16GB 显存即可推理，契合课程算力条件；官方架构原生支持文本指令（`--input_text`），与扩展方向直接契合且研究空间大。

### 3.2 主要使用者 / 使用场景

一句话：为**游戏测试/内容验证人员**提供一个"可被文本指令指挥"的 AI 游戏操作智能体——输入画面与一句指令，输出符合意图的键鼠动作。

### 3.3 课内交付边界

课内环境受限，明确如下交付边界：

- **无真机外设**：不依赖真实游戏环境与 Windows Recap 双卡方案；
- **算力受限**：仅推理与评测，不做微调（官方 8×H100 预算折算后算力不足）；
- **交付形态**：以**离线推理 + 评测 + 对比录屏**为主，不承诺实时端到端 <50ms 链路。

## 6. 主路径与验收标准

### 6.1 主路径（一次评测的可复现流程）

```
select_testset.py → testset.json（≤200 帧，冻结）
        ↓
启动推理服务器 inference.py（UDS: /tmp/uds.recap）
        ↓
p2p_client.InferenceClient.run(frames)   # 发帧收动作
        ↓
evaluate.py        # 读标注 + 模型输出 → 指标 CSV
        ↓
summarize.py       # 汇总指标表（对照验收线）
record_demo.py     # 对比录屏（M4）
```

### 6.2 验收标准口径（可量化）

- **按键准确率** = 预测按键集合完全匹配标注的帧数 / 总帧数（含空集），达标 ≥55%；
- **鼠标相关系数** = 预测位移序列与标注位移序列的 Pearson `r`，达标 ≥0.5；
- **任务完成率**（扩展）= 判定完成的片段数 / 指令片段总数，每个片段定义可自动判定的完成标准（如"累计左移 >50px 且按过左移键"），避免主观判定。

上述口径均已在立项书第六节形成公式化定义，可直接编码进评测脚本。

## 7. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| HuggingFace 登录/Gemma tokenizer 认证失败 | 无法加载模型 | 提前 `huggingface-cli login`；检查点与 tokenizer 本地缓存；准备代理/镜像 |
| 文本指令模式编译约束（仅启动时指定） | 实验设计受限 | 带/不带指令分别启动两个推理进程；提前固定指令文本集合 |
| full-data 下载量大、网络慢 | 进度延误 | MVP 阶段只用 toy 数据；full-data 按需下载 batch 1–5 |
| 显存/算力不足 | 微调无法进行 | 扩展方向以"预训练模型 + 指令"为主，不依赖微调 |
| 指标不达标（按键/鼠标） | 无法通过验收 | 检查帧对齐与评测口径；选标注更稳定的单一游戏；必要时补 full-data 同游戏帧 |
| Windows 实时推理复杂 | 影响演示形式 | 以离线评测 + 录屏对比满足 M4，实时推理作为可选项 |
